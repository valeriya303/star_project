# Star — інтерактивний локатор та навігатор зоряних каталогів

Вебсистема з інтерактивною WebGL-картою зір каталогу Hipparcos. Можна шукати й фільтрувати зорі, бачити небо над Львовом або над своїм місцем,
вести журнал спостережень і обмінюватися знімками сузір'їв через модерацію. Принцип **Data Governance by Design**: усі права доступу,
згоди та правила якості даних перевіряються на сервері (AD-03).

| Шар | Технологія (табл. 4.1) |
|---|---|
| Клієнт | React 19 + TypeScript, Three.js (WebGL) для зір, Canvas 2D для сітки й підписів, astronomy-engine |
| Сервер | Python FastAPI, Pydantic + JSON Schema (Draft 2020-12), OpenAPI (`/api/docs`) |
| БД | PostgreSQL + `pg_trgm` (у Docker), SQLite для локального запуску |
| Файли | MinIO (S3) у Docker, локальна тека для розробки |
| Автентифікація | JWT + bcrypt, серверні сесії з відкликанням |

## Швидкий запуск без Docker

```bash
# 1. Бекенд (Python 3.11+)
cd backend
pip install -r requirements.txt
# Покладіть датасет у backend/data/hipparcos-voidmain.csv
AUTO_IMPORT_CSV=data/hipparcos-voidmain.csv python -m app.cli bootstrap   # первинний імпорт (~10 с)
uvicorn app.main:app --port 8000

# 2. Фронтенд (Node 22)
cd frontend
npm ci
npm run dev        # http://localhost:5173, запити /api проксуються на :8000
```

Шрифт Kyiv Type Titling покладіть у `frontend/public/fonts/` (KyivTypeTitling-Regular.woff2, -Bold.woff2); без нього заголовки використовують запасний шрифт.

## Запуск у Docker (PostgreSQL + MinIO)

```bash
cp <шлях>/hipparcos-voidmain.csv backend/data/
docker compose up --build      # http://localhost:8080
```

## Розгортання в інтернеті (Render.com)

Один контейнер (кореневий `Dockerfile`) збирає React і запускає FastAPI, який віддає і сайт, і `/api`.
База — керований PostgreSQL від Render; знімки зберігаються в таблиці `stored_files` (`STORAGE_BACKEND=db`),
бо диск безкоштовного контейнера очищується при кожному перезапуску.

1. Залийте проєкт у GitHub (разом із `backend/data/hipparcos-voidmain.csv`).
2. На render.com: **New → Blueprint** → оберіть репозиторій. `render.yaml` створить БД `star-db` і сервіс `star`.
3. Введіть `DEMO_PASSWORD` — пароль тестових акаунтів (не `Star-demo-2026`).
4. Перший запуск ~3–5 хв: імпорт каталогу, ліній сузір'їв і демо-даних (`python -m app.cli deploy-init`).
   Повторні запуски нічого не дублюють.

Обмеження безкоштовного плану: сервіс «засинає» після 15 хв без запитів (перше відкриття ~1 хв),
безкоштовна БД діє 30 днів.

## Рішення, які варто погодити з командою

* **Датасет.** Імпортовано головний каталог Hipparcos із Kaggle (ліцензія CC0). Правила DG-5 сформульовані для HYG v4, тому імпорт має два профілі: `hipparcos` (RAdeg у градусах, відстань = 1000 / Plx, якщо Plx > 0) і `hyg` (ra у годинах, 100 000 пк → null). Із 118 218 записів 263 відхилено за QR-02 (немає координат), 113 прийнято з попередженням QR-09.
* **Назви зір і сузір'їв** взято зі Stellarium (modern) з українським перекладом Stellarium. Кілька назв сузір'їв уточнено вручну (Кит, Волопас, Кіль, Жертовник, Косинець, Гідра, Південний Хрест, Південна Гідра).
* **Числові пороги** «потребують погодження» за UC-12, тому винесені в конфігурацію: 50 балів за знімок, 3 нарахування на добу (доба — Europe/Kyiv). Поріг «швидкої зорі» — 500 мс/рік.
* **Шкали оцінок 1–5** (QR-22, QR-23) підписані в інтерфейсі: яскравість від «ледь помітна» до «дуже яскрава», умови від «дуже погані» до «відмінні».
* **Коди аудиту.** UC-06, UC-09, UC-15 вимагають фіксувати події, для яких у табл. 2.27 немає кодів, тому додано AUD-17…AUD-29.
* **record_hash** охоплює незмінні поля без `actor_id`/`object_id`. Так анонімізація за DG-7 не руйнує перевірку цілісності журналу.
* **Сервер рахує видимість** аналітично (власний рух, прецесія за Meeus, рефракція) замість Skyfield, бо для зір не потрібен файл ефемерид. Клієнт обчислює горизонтальні координати в реальному часі через astronomy-engine.
* **Скидання пароля.** Поштового сервісу немає, тому посилання друкується в консолі сервера.
